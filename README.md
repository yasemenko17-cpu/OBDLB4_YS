# Стартовий проєкт OBDZ-LAB03

1. Відкрийте проєкт у GitHub Codespaces (Code → Codespaces → Create codespace): разом із середовищем стартує сервер PostgreSQL 18 (з підключеним `pg_stat_statements`), а в терміналі доступна команда `psql`. Локально: `python3 -m venv .venv`, `source .venv/bin/activate`, `pip install -r requirements.txt` і окремо запустіть PostgreSQL 18, наприклад `docker run --name lab-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:18`. Якщо порт 5432 зайнятий, змініть лівий номер у `-p 55432:5432` і задайте `PGHOST=localhost`, `PGPORT=55432`.
2. Визначте свою задачу й набір за номером варіанта: задача = `(номер - 1) // 3 + 1`, набір = `(номер - 1) % 3 + 1`. Відкрийте `variants/lab_NN.py`, впишіть `VARIANT = <ваш номер>` і реалізуйте функцію за карткою варіанта в `student.md`.
3. Запускайте відкриті тести своєї задачі: `pytest tests/test_lab_NN.py` (тести інших наборів позначаються як пропущені). Усі тести звертаються до PostgreSQL: перевірте змінні PGHOST, PGPORT, PGUSER, PGPASSWORD (у Codespaces вони вже задані; типові значення localhost, 5432, postgres, postgres). Першого запуску у сеансі тести створюють великі таблиці (до 120 000 рядків) у тимчасових схемах; після завершення схеми видаляються.
4. Подивитися, що робить ваша функція, і побачити плани запитів до та після індексів можна командою `python try_it.py N` (N це номер задачі).
5. Тести фіксують параметри планувальника (`jit`, `max_parallel_workers_per_gather`, `default_statistics_target`, `random_page_cost`, `effective_cache_size`) і перевіряють тип вузла плану та використаний індекс, а не час виконання. Тому результат не залежить від швидкості комп'ютера. Для власних дослідів в `psql` задайте ті самі параметри командою `\i session.sql`.
6. Змінюйте лише свій файл у `variants/` і теку `project/` (за бажанням додавайте `tests/test_my.py`). Файли в `tests/` і `project_check/` не редагуйте.
7. Частина Б: перенесіть проєкт із лабораторної роботи 2 (база вашого дипломного проєкту) у теку `project/`, додайте теку `analytics/` (масштабування даних, 5-6 запитів, індекси, звіт) і перевірте командою `pytest project_check`. Розгорнути проєкт у схемі `project` вашої бази для ручних дослідів: `python project_check/deploy_project.py`.
